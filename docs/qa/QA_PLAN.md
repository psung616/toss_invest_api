# QA 계획 — 역할 분배와 테스트 프로세스

> 은행·증권사 IT 의 테스트 조직 관행(독립 검증, 역할 분리, 결함 등급, 진입·종료 기준, 변경관리 승인)을
> 1인 개발 + Claude Code 환경에 맞게 줄인 것. `docs/PRINCIPLES.md`·`CLAUDE.md` 가 이 문서보다 우선한다.

### 역할 분리 원칙 (금융권 "개발·검증 분리")
- QA 에이전트는 **운영 코드(`src/main`)를 수정하지 않는다.** 결함을 보고하고, 필요한 테스트 케이스를 제안만 한다.
  수정은 개발 작업(작업 ID 단위)으로 별도 진행한다.
- 같은 변경을 만든 세션이 스스로 "통과" 판정하지 않는다 → 판정은 QA 리드가 에이전트 보고를 모아 내리고, 릴리스는 사람이 승인한다.
- 실제 키·실계좌가 필요한 검증은 **사람만** 한다 (CLAUDE.md: `serve`·`setup`·`liveTest` 실행 금지).

## 2. 테스트 레벨

| 레벨 | 내용 | 담당 | 자동화 |
|---|---|---|---|
| 단위 | 클래스 단위 로직 (파서, 가드레일, 마스킹, 리미터) | 개발 + 기능/보안 에이전트 검토 | `./gradlew test` |
| 통합 | `MockRestServiceServer` 로 HTTP 파이프라인, 스프링 컨텍스트 | 기능·안정성 에이전트 | `./gradlew test` |
| 아키텍처 | 허용 호스트·패키지 의존·double 금지 | 보안 에이전트 | `ArchitectureTest` |
| 시스템 | jar/exe 를 키 없이 실행 (`--help`, 키 없음 처리) | 설치·UX 에이전트 | 수동 명령 |
| 인수(UAT) | 실제 키로 setup → Claude 에서 조회 → DRY RUN 주문 → 소액 실주문 | 👤 | 체크리스트 |

## 3. 결함 등급 (금융권 4단계)

| 등급 | 기준 | 예 | 릴리스 |
|---|---|---|---|
| **S1 치명** | 돈·주문·비밀정보에 직접 영향, 원칙 위반 | 가드레일 우회 주문, 키가 로그·stdout·저장소에 노출, 허용 외 호스트 통신 | **즉시 중단·No-Go** |
| **S2 높음** | 핵심 기능 실패 또는 사용자를 오도 | 실패했는데 성공으로 표시, 잘못된 금액 표시, 조회 불가 | **No-Go** |
| S3 보통 | 우회 방법이 있는 기능 결함 | 특정 입력에서 오류 문구 부정확 | 조건부 Go (기록 필수) |
| S4 낮음 | 표시·문구·편의 | 오타, 정렬 | Go |

## 4. 프로세스 (`/qa <범위>` 한 번이 1 사이클)
1. **계획** — QA 리드가 범위(작업 ID·변경 파일·기능)를 정하고 영향받는 역할을 고른다.
2. **분석** — 요구사항 분석가가 `TASKS.md` 완료 기준·`PRINCIPLES.md`·스펙 노트에서 검증 항목(추적표)을 만든다.
3. **실행** — 역할 에이전트가 병렬로 검토·테스트 실행 → 각자 표준 형식(§5)으로 보고.
4. **결함 관리** — QA 리드가 중복 제거·등급 확정 → `docs/qa/DEFECTS.md` 에 등록.
5. **판정** — 릴리스 관리자가 종료 기준(§7) 대비 Go/No-Go 의견 → 👤 최종 승인.
6. **보고** — `docs/qa/reports/YYYY-MM-DD-<범위>.md` 에 요약 저장.

## 5. 에이전트 보고 형식 (모든 역할 공통)
```
## <역할> 보고 — <범위>
- 검토 대상: 파일·작업 ID
- 실행한 것: 명령/테스트 이름과 결과(통과 n / 실패 n)
- 확인한 항목: [통과] / [실패] / [확인 불가: 이유] 체크리스트
- 결함 후보:
  - 제목 / 제안 등급(S1~S4) / 위치(파일:줄) / 재현 절차 / 기대 결과 / 실제 결과 / 근거
- 제안 테스트 케이스: (코드 작성 없이 이름·입력·기대값만)
```
보고서에 **실제 키·토큰·계좌번호·accountSeq·잔고·공인 IP·개인 경로를 쓰지 않는다** (저장소 public).

## 6. 인수 테스트(UAT) 체크리스트 — 👤 사람만
| ID | 절차 | 기대 결과 |
|---|---|---|
| UAT-01 | 키 입력 없이 [저장하고 연결 테스트] | 실패 안내, **등록·"완료" 표시 없음** (DEF-001) |
| UAT-02 | 잘못된 키 입력 | `invalid_client` 안내, 완료 표시 없음 |
| UAT-03 | 허용 IP 미등록 상태에서 올바른 키 | IP 등록 안내 |
| UAT-04 | 올바른 키 + 허용 IP | 연결 성공 → Claude Code 등록 → 완료 |
| UAT-05 | Claude Code `/mcp` | `tossinvest` Connected |
| UAT-06 | "삼성전자 현재가 알려줘" | 종목 검색 → 현재가 표시 |
| UAT-07 | "매수 가능 금액 알려줘" | 금액 표시 (채팅 밖으로 공유 금지) |
| UAT-08 | `ENABLE_ORDERS=true`, `DRY_RUN=true` 로 1주 매수 요청 | preview → 동의 → DRY RUN 기록, 실주문 없음 |
| UAT-09 | 한도 초과·허용 외 종목·장 마감 후 주문 | 미리보기 단계에서 거부 사유 표시 |
| UAT-10 | `reset-keys` | 키·토큰 캐시 삭제, 이후 조회 시 setup 안내 |
결과는 통과/실패와 화면 문구만 공유한다 (키·금액·계좌 정보 제외).

## 7. 진입·종료 기준
- **진입**: `./gradlew check` 통과, 범위 작업의 `TASKS.md` 완료 기준 충족 주장, 변경 파일 목록 확정.
- **종료(Go)**: S1·S2 미해결 0건, S3 은 대장에 기록·사람 확인, 해당 UAT 항목 통과(사람), 보안·컴플라이언스 에이전트 "원칙 위반 없음".
- **No-Go**: 위 중 하나라도 미충족. 재작업 후 해당 역할만 재검증(회귀는 `./gradlew check` 전체).
